## 30s / 1min / 3min 项目介绍

**30s（电梯版）**：
测试金字塔架构的 OrangeHRM 自动化项目：API 层做业务规则主力，UI 层测关键用户
旅程，本地 Docker 加 DB 持久化校验。19 场景 18 通过 + 1 个设计为红的负对照。
失败自动留痕（截图/Trace/双日志）保证 5 分钟定位；另有分层 CI workflow 与
Docker 化测试环境。

**1min（有证据版）**：（30s 内容 + 三个实测证据）
- API 比 UI 快约 3 倍（同环境），所以业务规则测试放 API 层
- 公网过载令 goto 随机超时（Builder 5P / Reviewer 3P+2E 并存），做了超时校准 +
  单次重试 + **可观测计数**（能区分"flaky 消失"与"被重试救回"）
- 共享环境数据污染（3 分钟 +1 条），所以数据工厂唯一命名 + 自建自清

**3min（有故事版）**：（1min 内容 + 排障故事）
- 登录接口六轮证伪：5 种"合理猜测"全错，Playwright 网络监听一次定音
- DB 硬删 vs 软删：API 视角无法区分，只有查库知道（employee_id NULL / 行物理消失）
- 断言 5s 盲区：expect 默认 5s 不受 set_default_timeout 管，M5 全量时才暴露
- 门禁事故：一次审查结论由实现方代笔，被所有者作废、状态回退，沉淀为团队制度——
  面试官通常会对这个"质量流程本身被审查"的故事感兴趣
