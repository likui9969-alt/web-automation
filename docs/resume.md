## 简历 bullet（4 条主 + 1 条缺陷发现补充）

   覆盖登录鉴权 / PIM CRUD / 混合闭环等 19 场景；同环境实测 API 层较 UI 快约 3 倍、
   本地确定性环境较公网快约 4~9 倍（视时段与用例集）——分层配比有实测依据而非拍脑袋。
2. **可复用测试基础设施**—— 数据工厂唯一命名（共享 Demo 环境防数据污染，实测
   3 分钟内他人造数 +1 条）、fixture 三层 scope 管理浏览器生命周期、参数化消除
   复制；重构后用例数 +67% 总耗时持平（单例均摊 -38% 实测）。
3. **失败定位体系（测试工程化）**—— 失败自动留痕四件套：截图 / Playwright Trace /
   浏览器网络日志 / API 请求日志，落盘且成功零产物；集成 Allure（feature/severity/
   attachment），故意注入失败实测四类产物全部真实生成——失败 5 分钟内可定位。
4. **CI/CD 与容器化**—— 分层 CI workflow（API 先跑快反馈，任一层红即红）＋ 测试
   执行环境 Docker 化（一套 compose 命令容器内全量 18 passed）；flake 度量脚本
   量化公网稳定性（同命令 ×N 可复跑，3/3 记录在案）；浏览器路径走代码级配置根治。
   ⚠️ 真实 GitHub Actions 触发待上仓验证（当前如实标注 workflow 已就绪）。
5. **缺陷发现闭环（测试岗最值钱的点）**—— 通过跨层对比发现被测系统真实行为：
   ① API 创建的员工 employee_id 为 NULL（显示编号不走创建路径）；② API 删除后
   DB 行**物理消失**（purged_at 软删字段未启用，硬删 vs 软删仅查库可区分）；
   ③ 登录接口六轮探测证伪（表单/JSON/UA 全错，网络监听定音 token 真实路径）。

## 30s / 1min / 3min 项目介绍

**30s（电梯版）**：
测试金字塔架构的 OrangeHRM 自动化项目：API 层做业务规则主力，UI 层测关键用户
旅程，本地 Docker 加 DB 持久化校验。19 场景 18 通过 + 1 个设计为红的负对照。
失败自动留痕（截图/Trace/双日志）保证 5 分钟定位；另有分层 CI workflow 与
Docker 化测试环境。

**1min（有证据版）**：（30s 内容 + 三个实测证据）
- API 比 UI 快约 3 倍（同环境），所以业务规则测试放 API 层
- 公网过载令 goto 随机超时（Builder 5P / Reviewer 3P+2E 并存），做了超时校准 +
  单次重试 + **可观测计数**（能区分"flaky 消失"与"被重试救回"）
- 共享环境数据污染（3 分钟 +1 条），所以数据工厂唯一命名 + 自建自清

**3min（有故事版）**：（1min 内容 + 排障故事）
- 登录接口六轮证伪：5 种"合理猜测"全错，Playwright 网络监听一次定音
- DB 硬删 vs 软删：API 视角无法区分，只有查库知道（employee_id NULL / 行物理消失）
- 断言 5s 盲区：expect 默认 5s 不受 set_default_timeout 管，M5 全量时才暴露
- 门禁事故：一次审查结论由实现方代笔，被所有者作废、状态回退，沉淀为团队制度——
  面试官通常会对这个"质量流程本身被审查"的故事感兴趣
