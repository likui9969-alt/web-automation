## 四、答案三：思考题

### Q1 为什么不能把所有测试都写成 UI 自动化？（至少 4 个角度）

1. **速度**：UI 用例要启动浏览器、渲染、模拟真实输入（今天实测每次登录提交后还有 1~3 秒 SPA 重渲染瞬态），单条 5 秒起步；API 用例毫秒级。规模到几百条时 CI 从分钟级恶化到小时级，反馈太慢的自动化会被团队抛弃。
2. **稳定性**：UI 链路 = 网络 → JS 加载 → 渲染 → 动画 → 事件，任何一环抖动都失败。今天亲手复现了瞬态空窗——这就是 flaky 的典型来源。
3. **维护成本**：前端改版（哪怕只是 OXD 组件库升级改 class）就让定位器成片失效；接口契约相对稳定得多。
4. **断言粒度**：UI 只能断言"渲染出来的表象"；API 能断言完整数据结构、状态码、响应时间、schema 契约。
5. **组合爆炸**：业务规则（非法输入、边界、权限组合）数量大，API 参数化能低成本全覆盖，UI 只挑关键旅程。

**结论**：UI 留给"真实用户路径"，业务规则下沉 API——这就是测试金字塔的实践依据。

### Q2 Demo 数据被别人改、被重置，测试设计怎么保证稳定？

今天拿到两个**实时证据**：员工记录数在 3 分钟内从 (315) 变成 (316)（有陌生用户添加了数据）；列表里满是其他人的 `Automation15165729`、`AutoTest_210001` 之类的测试数据。

对策（按优先级）：
1. **不依赖固定数据断言**：禁止"搜索 Linda 断言 1 条结果"这类写法——总数、他人数据都在变
2. **自己造数 + 唯一命名**：数据工厂用时间戳/随机后缀（今天看到的其他测试者的命名习惯证明这是通行做法）
3. **断言只指向自己造的数据**：搜自己的唯一 ID，验证存在即可
4. **用例结束清理**：写操作造的数据删除或标记，保证可幂等重跑
5. **结构性断言替代数据性断言**：断言"搜我的 ID → 恰好 1 条"，不断言"第 N 行是谁"
6. **公共账号只做只读验证**：admin 不改密码、不动公共配置（见 LOGIN-14 决策）

### Q3 "添加员工成功"的 UI 断言和 API 断言有什么本质区别？

**本质区别：验证的是三个不同层面的"真"。**

| 层 | 验证对象 | 能抓到的缺陷 |
|----|----------|--------------|
| UI | 用户看到的渲染结果（表象） | 后端返回正确但前端渲染 bug、提示文案错误 |
| API | 数据契约（结构/字段/状态码） | 页面显示成功但响应实际是 4xx、字段丢失、部分成功 |
| DB | 持久化事实（真相） | 接口返回成功但事务未提交、写错表、数据不一致 |

1. UI 提示 "Success" 只证明**前端按预期渲染了成功状态**，不证明数据正确落库——前端可能吞掉了错误，或后端返回了 200 但内容错误
2. 今天的实证：页面显示 "(315) Records Found"，一分钟后变成 316——**UI 上看到的数字本身就是易变的共享状态**，不能作为稳定断言对象
3. 工程实践：写操作 = UI 验证关键旅程 + API 验证响应契约 + DB 验证落库（M6 后补全第三层），三层对得上，才算真正通过
4. 补充一层：错误提示。今天验证了 "Invalid credentials" 同时覆盖"用户不存在"和"密码错误"——只有分层验证才能确认这是**防枚举设计**而非 bug

## 五、附加发现（直接影响 M1–M5 设计）

| # | 发现 | 影响 |
|---|------|------|
| F1 | 共享环境实时污染（315→316） | 数据工厂唯一命名是硬要求，写进 M5 验收标准 |
| F2 | SPA 每次登录提交后 1~3 秒 DOM 瞬态空窗 | M1 等待策略必须"等元素出现"而非固定 sleep——flaky 治理第一课 |
| F3 | 会话 Cookie 为 HttpOnly | M4 requests 必须走 `Set-Cookie` 响应头建 Session，不能从页面 JS 取 |
| F4 | OXD 组件类名体系（`oxd-alert-content-text`、`orangehrm-login-forgot-header` 等） | M3 POM 定位器策略依据：优先语义化 role/label（Playwright get_by_role），OXD 类名作次选 |
| F5 | "Forgot your password?" 是 `<p>` 元素而非 `<a>` | 定位器不能想当然用 link role——逐个实测是必要的 |
| F6 | 搜索表单默认折叠，按钮 offscreen，需 toggle + scrollIntoView | M1 UI 自动化要处理折叠面板/滚动可见性；也是"元素不可见"报错的活案例 |
| F7 | 侧边栏点击未触发路由跳转（单次观察，直接 URL 导航正常） | 已记入风险清单，**原因未诊断**，M1 用 Playwright 复验后再定论 |
| F8 | Employee Name 搜索是 autocomplete（"Type for hints..."），Employee Id 是普通输入 | 测试优先用 Employee Id 精确定位数据，避开 autocomplete 时序问题 |
